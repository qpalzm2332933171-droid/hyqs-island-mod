# 渠道服移植教程(把 MOD 打到其它渠道的 APK 上)

> 本仓库成品现有 **OPPO / vivo / 九游(UC) 三个渠道**(实测记录见 README 第 8.7 节)。
> 本文给出一套通用流程 + 排查表, 适用于魅族 / 小米 / QQ 等其它渠道。
> 本项目已在 MUMU 模拟器(x86)上用此流程实测走通 OPPO / vivo / 九游 三渠道; 其余渠道按此流程自行验证。

## 1. 渠道差异在哪

| 差异点 | 是否要改 | 说明 |
|---|---|---|
| 包名 | ❌ 不改 | 服务器用包名/渠道号做校验(`/user/packagecheck`) |
| 渠道号 | ❌ 不改 | 由原生 `DYCommon.channelName()` 提供(源码行 6568) |
| 渠道 SDK | ⚠️ 少动 | 登录/支付 aar; apktool 解包时建议 `-s` 保留原 dex 不变 |
| 游戏逻辑 jsc | ✅ **要用渠道自己的** | 登录/支付/广告分支按渠道走 |
| 图标资源 | ✅ 加 | `assets/hymod/icons/*.png` |
| MOD 代码 | ✅ 加 | 追加到 jsc + `classes2.dex` + manifest provider |

已知渠道号(源码行 39870-39878 的常量表):

```
DAYU(大禹/TapTap) 300007      OPPO 000020       OPPO支付 000021
MEIZU 000014                  MI(小米) 000066    UC(九游) 000255 / 000256
QQ 游戏 000553                vivo 000368
```

## 2. 完整流程

### 2.1 解包(保留原 dex)

```bash
apktool d -f -s -o work/apk_dec target.apk    # -s: 不反编译 dex, 只解资源/清单
```

### 2.2 解密目标渠道的 project.jsc

```bash
python mod/tools/jsc.py unpack work/apk_dec/assets/src/project.jsc /tmp/target_project.js
```

- 成功 -> 直接继续;
- 报 `not a zip after xxtea` -> key 不是 `ebf83d12-bc75-4b`, 用 Frida 动态抓:

  ```bash
  pip install frida
  python mod/tools/dump_xxtea.py --pkg <目标包名> --out dump
  # 出来的 xxtea_*.bin 其实是 zip, 解开取 encrypt.js
  ```

### 2.3 追加 MOD 并重新加密

```python
import io, sys
sys.path.insert(0, "mod/tools")
import jsc
game = io.open("/tmp/target_project.js", encoding="utf-8").read()
mod  = io.open("mod/js/mod_native.js", encoding="utf-8").read()
print(jsc.pack((game + "\n" + mod).encode("utf-8"), "work/apk_dec/assets/src/project.jsc"))
```

> 也可以直接让 `build_apk.py` 用 `game-source/project.dec.js` 拼(同版本时内容基本一致),
> 但**跨渠道推荐用渠道自己的 jsc**, 避免 SDK 分支差异。

### 2.4 三个资源改动

1. `python mod/tools/patch_manifest.py` -> 往 AndroidManifest.xml 里插 `com.hymod.ModProvider`;
2. `cp mail-tool/icons/*.png work/apk_dec/assets/hymod/icons/` -> 物品选择器的图标;
3. (可选) 如果该渠道的 Activity 类名不含 `DYGame`/`Cocos2dxActivity`,
   改 `ModProvider.maybeAttach()` 里的判断, 或者先跑一次
   `adb shell dumpsys activity activities | grep -i <包名>` 看真实类名。

   > 实测 OPPO / vivo / 九游 三渠道的启动 Activity 都是 `com.dygame.common.DYGame`, 无需改动。

### 2.5 编译 dex + 打包 + 签名

```bash
python mod/tools/build_dex.py     # javac + d8 -> classes.dex
python mod/tools/build_apk.py     # apktool b -> 注入 classes2.dex -> zipalign -> apksigner
# 产物 dist/荒野日记孤岛_MOD.apk
```

需要的环境变量(不设也行, 脚本会自动找):

```
ANDROID_SDK_ROOT / ANDROID_HOME   Android SDK 路径
JAVA_HOME                         JDK
HYQS_KEYSTORE / HYQS_KS_PASS / HYQS_KS_ALIAS   自己的签名
HYQS_APKTOOL                      apktool.jar 路径
HYQS_WORK                         工作目录(默认 <repo>/work)
```

### 2.6 安装验证

```bash
adb uninstall <包名>
adb install -r dist/荒野日记孤岛_MOD.apk
adb logcat -s HYMOD:* | findstr /i "hymod"    # 看日志
```

正常的话会看到:

```
ModProvider init ok
copyModJs overwrite 1 file(s)
[HYMOD] MOD v3.1.0 已加载 (原生菜单)
[HYMOD] 菜单已下发 (xxxx 字节)
```

## 3. 排查表

(与 README 第 8.5 节相同的表, 这里按"原因"再归类一次)

**A. 装不上 / 闪退**

- 签名冲突 -> 先 `adb uninstall`;
- `classes2.dex` 不存在 -> 跑 `build_dex.py`;
- ABI 不匹配 -> 在 APK 里只保留目标 ABI 的 `lib/`(或装 universal 版);
- provider 声明写错(authority 与别的 app 冲突) -> 改 authority。

**B. 能进游戏但没有菜单**

- `logcat` 里没有 `ModProvider init ok` -> manifest 没插进去 / dex 没注入;
- 有 log 但没有菜单 -> Activity 类名不匹配, 改 `maybeAttach()`;
- 有菜单但点开是空白 -> JS 层没起来, 看 `logcat` 里的 `[HYMOD]` 日志。

**C. 菜单能用但玩一会就没了**

- 被热更覆盖 -> 检查"安全"页的"拦截热更"是否开启; 检查 `copyModJs` 日志。

**D. 登录失败**

- 登录时开着抓包 -> 先关抓包再登录(这是最容易忽略的一条);
- 渠道 SDK 校验签名 -> 试着用原 APK 的签名(需要你自己的签名 key, 一般拿不到), 或者用 Frida 方案;
- jsc 用了别渠道的 -> 换回该渠道自己的 jsc。
